# 6.5 NoSQL数据库

NoSQL 常被解释为“Not Only SQL”，泛指采用非关系数据模型的一类数据库。事务支持及 ACID 保证取决于产品和操作范围，例如 MongoDB 支持多文档事务。

## 6.5.1 分类与特点

当前出现了很多不同类型、面向不同应用的NoSQL 产品，按主要逻辑数据模型，可介绍以下四种常见类型；有些产品支持多种模型。

### 1. 宽列（列族）数据库

行式和列式描述物理存储布局：行式按记录组织数据，列式把同一列的值放在一起。关系数据库也可以采用列式存储。本节所列的宽列数据库是一类逻辑数据模型。

宽列数据库常用于大规模分布式数据存储。数据可按键及列组织，相关列可按列族管理。典型产品有 Cassandra 和 HBase。

### 2. 键值对存储数据库

键值数据库通过键访问与之关联的值。哈希表是可能的实现之一，例如可由哈希码确定桶，再在桶内查找键；键值模型也可采用其他索引结构。

键值模型直接按键查找，接口通常比较简单。如果应用需要按值内部字段筛选或更新，效率取决于产品是否支持相应操作或索引。产品例子有 Tokyo Cabinet/Tyrant、Redis、Voldemort、Oracle Berkeley DB 和 Riak KV。

### 3. 文档型数据库

文档数据库以文档为基本数据单元，常用 JSON 或类似格式表示半结构化数据，并允许嵌套字段。有些产品支持按文档字段建索引和查询；版本管理和查询性能取决于产品及访问方式。产品例子有 CouchDB、MongoDB 和 SequoiaDB。

### 4. 图数据库

图数据库以节点和边表示实体及其联系，适合处理社交网络、生物信息网络和交通网络等关系数据。查询语言、API 及多服务器扩展能力取决于产品。常见例子有 Neo4j、InfoGrid 和 InfiniteGraph。

不同 NoSQL 产品面向不同场景，选型时可以考察以下特点：

- 易扩展：部分产品通过分片把数据和负载分布到多个节点。扩展效果取决于分片键、负载分布和跨节点访问。
- 大数据量和性能：针对特定访问模式组织数据，有助于提高相应操作的吞吐量；应按实际数据量与读写负载测试。
- 灵活的数据模型：有些产品允许记录或文档包含不同字段，另一些要求预先定义结构。
- 高可用：部分产品通过复制和故障切换提高可用性，效果及代价取决于副本配置和一致性要求。

## 6.5.2 体系框架

本节以四层模型说明 NoSQL 数据库的主要职责，由下至上分为数据持久层（Data Persistence）、数据分布层（Data Distribution Model）、数据逻辑模型层（Data Logical Model）和接口层（Interface），层次之间相辅相成，协调工作。

1. 数据持久层描述存储方式，包括基于内存、基于磁盘、内存与磁盘结合，以及使用可插拔的存储引擎。内存访问通常较快，故障后能否恢复已确认的写入，还取决于日志、刷盘和复制策略。
2. 数据分布层描述分片、复制及节点调整方式。分片可用于水平扩展，副本可分布在多个数据中心。CAP 定理讨论网络分区时一致性与可用性的取舍；实际跨中心运行和在线增减节点的能力取决于产品及配置。
3. 数据逻辑模型层规定数据的组织方式，例如键值、文档或图，以及适用于该模型的操作。
4. 接口层为上层应用提供访问数据的途径。例如，产品可以提供 REST 接口、Thrift 服务、Get/Put 操作或特定语言的 API，有些还提供 MapReduce 计算接口。

这一分层可用来比较不同产品的设计选择；同一产品可能提供几种接口或存储方式，具体组合和兼容性取决于实现。

可根据数据模型、访问模式、性能和一致性要求评估是否采用 NoSQL。例如：

- 数据模型比较简单；
- 需要灵活性更强的IT系统；
- 对数据库性能要求较高；
- 产品的一致性和事务保证能满足业务要求；
- 给定键可直接定位复杂值，以按键访问为主。
