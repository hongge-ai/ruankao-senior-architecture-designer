# 6.4 应用程序与数据库的交互

在普通的情况下，用户可以通过SQL和过程性 SQL（如 PL/SQL、T-SQL 等）来访问数据库中的数据。但是在应用系统中，需要高级程序语言来完成与用户之间的交互，最终用户通常通过应用接口访问后台数据库。因此数据库管理系统需要提供程序级别的接口来访问数据。常见应用程序与数据库的数据交互方式有库函数、嵌入式SQL、通用数据接口标准和对象关系映射（Object-Relational Mapping，ORM）等。

## 6.4.1 库函数级别访问接口

库函数级别的数据访问接口往往是数据库提供的最底层的高级程序语言访问数据接口，如Oracle数据库的Oracle Call Interface（OCI）。开发者可以使用高级程序语言编写程序实现人机交互和业务逻辑，而使用OCI来访问数据库。

OCI 是 Oracle 客户端库提供的应用程序编程接口（API）。应用程序通过库函数连接数据库、执行 SQL 语句和控制事务。使用 OCI 的应用需要相应的 Oracle 客户端库，是否已安装取决于所选的软件包。

OCI开发方法实际上是将结构化查询语言（SQL）和高级程序语言相结合的一种方法。对数据库的访问是通过调用OCI库函数实现的，若将C 语言作为宿主语言，那么Oracle数据库调用其实就是C 程序中的函数调用，应用程序可以在 C 代码中编排控制流程，通过 OCI 执行 SQL 或调用数据库中的 PL/SQL 程序。

OCI开发方法的缺点是往往强依赖于特定的数据库，需要数据库开发人员对该数据库机制有较深的理解，学习难度较大，开发效率不是很高。

## 6.4.2 嵌入SQL访问接口

嵌入式 SQL（Embedded SQL）是一种将SQL语句直接写入某些高级程序语言，如C、COBOL、Java、Ada等编程语言的源代码中的方法。借此方法，可使得应用程序拥有了访问数据以及处理数据的能力。

1989 年的 ANSI X3.168《Database Language — Embedded SQL》规定了 SQL 与 Ada、C、COBOL、Fortran、Pascal 和 PL/I 的嵌入方式。同期的 ANSI X3.135-1989 是带完整性增强的 SQL 标准。具体产品支持哪些宿主语言取决于实现，Oracle、Db2 等数据库提供相应的开发工具。

在这一方法中，包含嵌入式 SQL 语句的源程序所用的编程语言称为宿主语言。

提供对于嵌入式SQL的支持，需要能处理嵌入式 SQL 的工具链和运行时支持。为了实现对于嵌入式SQL的支持，技术上必须解决以下问题。

1. 宿主语言的编译器不能识别和接受SQL程序，需要解决如何将含有 SQL 语句的宿主语言源代码编译成可执行程序。
2. 宿主语言的应用程序如何与DBMS之间传递数据和消息。
3. 如何把对数据的查询结果逐次赋值给宿主语言程序中的变量，以供其处理。
4. 数据库的数据类型与宿主语言的数据类型有时不完全对应或等价，如何解决必要的数据类型转换问题。

为了解决上述这些问题，一种常见实现是先用预编译器处理含嵌入式 SQL 的源文件，把 SQL 语句转换成宿主语言的库函数调用。这样一来，源码即可使用宿主语言对应的编译器进行编译。通常情况下，经过嵌入式SQL的预编译之后，原有的嵌入式SQL会被转换成一系列函数调用。采用这种实现时，编译后的程序还需链接相应的运行时库。

嵌入式SQL中除了可以执行标准SQL程序之外，为了对应嵌入的需要，还增加了一些额外的语法成分。主要包括宿主变量使用声明、数据库访问、事务控制、游标操作的语法等。

## 6.4.3 通用数据接口标准

开放数据库连接（Open Database Connectivity，ODBC）为不同数据源提供统一的访问接口。应用程序可通过相应驱动访问不同 DBMS，也可在驱动支持时访问 Excel 工作表或文本文件。应用能否直接迁移，还取决于所用 SQL 方言和驱动能力。

基于 ODBC 的应用程序调用 ODBC API，由驱动程序管理器将请求交给相应驱动访问数据源。应用可以复用同一套接口，具体操作仍受驱动和数据源支持范围的限制。

应用可以用已配置的数据源名（DSN）建立连接，也可以在连接字符串中指定驱动及所需的连接参数，无须预先注册 DSN。

在微软的历史数据访问技术中，DAO、RDO 和 ADO 使用不同的对象接口封装数据访问操作。

- 数据访问对象（Data Access Objects，DAO）。这是微软用于访问 Jet 等数据引擎的对象接口，常用于 Access 等桌面数据库应用。
- 远程数据对象（Remote Data Objects，RDO）。这是微软对 ODBC 的对象封装，可用于访问支持 ODBC 的远程数据源，实际性能取决于驱动、查询和部署环境。
- ActiveX 数据对象（ActiveX Data Objects，ADO）。这是微软提供的数据访问接口，可通过 OLE DB 提供程序访问相应数据源，也可通过适配层访问支持 ODBC 的数据源。经典 ASP 页面可使用 ADO 脚本连接 SQL Server、Access 或 Oracle 等数据库。

ADO.NET是微软在.NET框架下开发设计的一组用于和数据源进行交互的面向对象类库。ADO.NET提供了对关系数据、XML 等数据的访问，允许和不同类型的数据源以及数据库进行交互。

Java 数据库连接（Java Database Connectivity，JDBC）是 Java 语言中用来规范客户端程序如何访问数据库的应用程序接口，提供了诸如查询和更新数据库中数据的方法。JDBC是一种用于执行SQL语句的Java API，可以为多种关系数据库提供统一访问，它由一组用Java语言编写的类和接口组成。

JDBC用于直接调用SQL命令，被设计为一种基础接口，在它之上可以建立高级接口和工具。

## 6.4.4 ORM访问接口

对象关系映射（Object-Relational Mapping，ORM）描述程序中的对象及其属性与关系数据库中的表、列等结构之间的对应关系。

ORM是通过使用描述对象和数据库之间映射的元数据，将程序中的对象与关系数据库相互映射；ORM可减轻对象模型与关系模型之间的转换工作。

ORM 可以将对象状态保存到关系数据库，并根据查询结果恢复对象。映射规则可用注解、XML 或框架约定来表达，持久层据此封装部分数据库访问细节。

ORM 可以减少手工编写常见映射和 SQL 的工作。开发者仍需了解数据模式、约束、事务及查询性能。Java 环境中可比较 Hibernate、MyBatis 与 JPA 的不同职责。

1. Hibernate 是对象关系映射框架，可按映射规则生成 SQL，也允许开发者编写查询。
2. MyBatis 是 SQL 映射框架，开发者可以编写 SQL，并配置参数及查询结果与对象的映射。
3. JPA（Java Persistence API，后续称 Jakarta Persistence）是 Java 对象持久化和对象关系映射的规范。可用注解或 XML 描述映射，运行时需要相应的实现。
